# 个性化建议与分步辅导模块设计

## 1. 模块目标

把“学习要求—已有表现—学习建议”落成一份可执行计划。计划必须引用真实记录、真实题号和真实材料，并把学生提示与教师解析隔离。

## 2. 输入与依赖

- 魏文宇：当前有效记录、个人统计、状态覆盖、证据查询。
- 宗博文：同题差异、同伴参考、班级概览和两班对照。
- 纪宏锋：课程指标索引、步骤诊断、依据和不确定事项。
- 王振宇：计划字段、三层提示、练习顺序、观察点和调整条件。

本模块接受统一`RecommendationRequest`，不读取或修改原始CSV中的状态。

## 3. 核心规则

1. 同一`event_id`只保留最高修订版本。
2. 待评分、未作答、无记录、零分、尚未教学分别处理。
3. 只根据已评分证据计算得分率；证据少于3条时结论标记为`provisional`。
4. 选择首要指标时优先考虑得分率最低且证据充分的指标；调用方可以指定诊断重点。
5. 没有足够证据时生成`coverage_probe`计划，不写“已掌握”或“未掌握”。
6. 每个计划至少包含概念复位、原题复盘、独立练习、迁移与检验、反思与退出。
7. 三层提示依次承担：激活概念、提供下一步操作、提供检查策略；不直接给答案。
8. 教师解析存放在`teacher_explanation`和`teacher_only`，学生端不渲染。
9. 调整条件必须写明“若……则……”，并与下一次观察相连。

## 4. 三个代表案例

### D01：部分得分

Q043当前有效版本为v2，得分1/3。评分点显示移项正确，但“除以负数时反向”和“写出并核对解集”均为0分。计划先复盘Q043，再用Q041独立练习，最后用Q042迁移“乘除负数改变方向”，并要求代值检查。

### D14：表现较好

D14已评分26条，得分率97.8%。唯一失分为Q026，将x=3误判为方程2x+1=7的解。计划用Q026检查“方程解”的定义，用Q022强化代回检验，再用Q034迁移到实际情境建模。

### D17：记录不足

D17只有T01的4条已评分记录，均为满分。计划明确“不能推断T02、T03已掌握”，先做Q022和Q039两项低负担探测，再依据提示层级决定下一次辅导。

## 5. 输出一致性

页面、JSON、CSV都读取同一份计划对象；所有数值由构建脚本生成。计划包含`evidence_used`、`material_refs`、`quality_checks`，支持复核与追溯。

## 6. 已知限制

- 模拟数据稀疏，部分指标只有少量题目，结论需要后续观察。
- 当前模块不生成最终学习成效结论，只支持教学决策。
- 真实部署时需要替换题库、课程索引和学生证据输入，但字段不变。
