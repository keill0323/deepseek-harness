# 智慧学伴本地分析

在本仓库根目录运行既有业务 CLI。Harness 负责选择和调度工具，统计与建议由本地规则引擎产生；模型会话不改变业务计算的来源，不能声称训练模型或验证真实教学效果。只有实际会话记录证明成功调用时，才可说明已使用模型调度。功能、安装和字段说明以 [业务运行说明](../../../modules/README.md) 为准。

## 数据与输出范围

赛事资料及模拟学生逐条记录只限本次比赛本地使用。默认输入目录为 `tmp/study-data/input`，本地派生文件写入被 Git 忽略的 `tmp/study-data/`。不得将原始 CSV、题目正文、学生作答、具体分数、诊断内容或完整 JSON 报告放进远程模型上下文，也不得上传到公网或提交 Git。

所有业务 CLI 调用必须带 `--summary-only`，工具输出仅保留本地产物路径、操作状态和一般运行提示。不要先运行普通输出再在模型中删减；不要用 `cat`、`Get-Content`、浏览器 DOM、截图识别或其他工具把本地报告详情读回模型。具体分析由用户在本地报告中查看，回复提供本地链接及如何选择学生、测验和功能。只有用户另有明确授权且主办方规则允许时，才可调整数据流转范围。

## 运行

先确认输入目录和已安装的项目依赖存在；缺少输入时说明需要哪一个本地目录，不构造赛事记录。依赖或构建有缺失时，按运行说明补齐，安装前说明内容、用途、位置及非全局安装。构建命令为 `npm run study:build`。

输入若明确为自编合成数据，所有 `run` 和 `export` 调用还必须追加 `--fixture`；不能用默认 `live` 标记冒充正式数据。已有构建产物和输入时直接调用，不重复安装或构建。批量请求分别使用 `--operation`、`--request-file` 和新的 `--out` 路径。

完整报告优先通过下列入口导出；为 `--out` 选择尚不存在的本地目录，不覆盖既有输入或验收结果。

```powershell
node modules/app/cli.ts export --data tmp/study-data/input --out tmp/study-data/reports/run-01 --summary-only
```

只需单项业务操作时，使用统一 `run` 入口和结构化请求；个人或班级统计请求必须给出测验节点。例：

```powershell
node modules/app/cli.ts run --data tmp/study-data/input --operation diagnose_student --request '{"student_id":"D01","node_id":"N02"}' --out tmp/study-data/requests/diagnosis-run-01.json --summary-only
```

将工具返回的本地报告或结果文件链接交给用户。操作失败时报告一般失败状态和修复条件，不把原始记录作为错误示例抄入回复。仅在业务操作实际成功后报告产物已生成；`needs_review` 和 `insufficient_data` 是有效但有适用限制的结果，不能说成已确认学生能力。

比较必须保留共同有效题集、同题权重和同伴排除本人的口径。课程引用、异常复核、步骤定位和提示内容由业务模块负责，不在对话中改写事实、代填缺失分数或将缺记录解释为未掌握。三级学生提示不直接给出最终答案；教师查看入口不等同于生产环境身份认证。
