# 学习指导模块

本模块使用本地规则，将指定节点的统计和诊断转为可执行的学习活动与分步提示，不调用远程大模型。`build_learning_plan(dataset, { student_id, node_id }, diagnosis?, statistics?)` 返回 `team-v1` 结果，包含活动目标、依据、实际题目与材料编号、先后顺序、观察方式和调整条件。协调入口可以复用同一次计算的诊断和统计；两者必须与数据版本、策略版本、生产者、来源及学生、节点一致，否则停止生成计划，只保留当前请求自身的统计事实。

有效失分记录优先形成针对练习；已有表现较好的覆盖范围安排解释、检验和迁移活动；缺少已教范围记录时安排补充观察。未作答、待评分和待复核评分不作为薄弱项依据，缺记录不判定未掌握；未教主题不列为当前薄弱内容。所有题目必须属于输入节点的允许题集，缺材料时说明限制，不编造题目或引用。补充有效作答与评分后重新运行，计划随新证据调整，不将点击完成或主观反馈等同于掌握。

明确定位到原始步骤的错误排在一般失分之前，活动附 `finding_ids` 并直接指向应核对的步骤。`selection_reason` 说明选题是具体错误、已有失分、同指标未尝试题，还是在没有新题时对已完成题做解释检验。待评分题先等待核对，不当作新练习重复安排；同题的其他有效事件可以保留其已有表现，复核记录仍不作为依据。学生方法提示分别处理消元、代入求值、公共解集及一般变形，不复制原题答案。

`activities` 保留全部当前范围活动，`phase` 将首轮最多三个任务标为 `first`，余项为 `follow_up`；`delivery` 给出两个阶段的活动编号、首轮上限和进入后续阶段的条件。无可靠错误根因需要先处理时，同类补充观察或解释活动在主题之间轮换，避免首轮只覆盖一个主题。阶段划分用于控制本轮任务数量，不能视为已验证的教学效果。

`get_hint(dataset, { student_id, node_id, item_id, level, mode? })` 接受三级提示，默认 `student` 模式。学生输出只给方法与检查顺序，不复制参考答案、完整解析或评分点。`teacher` 模式显式返回参考答案、解析和评分点；此模式是本地演示能力，不提供账号鉴权，部署前须由调用方限制访问。代码不使用题干中的指令生成自由文本提示；它按方法类别选取固定规则，并对参考答案文本重合再次过滤。

计划额外提供 `certainty`、`summary`、`evidence_gaps`；每项活动提供 `success_criteria`、`next_if_success`、`next_if_not`。九项正式指标使用指标级提示、观察点和调整规则，其他指标使用明确标注的通用回退。

`build_class_plan(dataset, { class_id, node_id }, analysis?)` 使用同版本、同班同节点的班级分析，按已教且有可用题目的指标生成针对练习、解释迁移和补充观察分组。每组列出适用学生、证据、材料、可选题目、实施步骤、观察点与调整条件。复核评分即使保留统计也不作为教学判断依据；分组不是全班能力排名。此入口位于 `class.ts`，统一 CLI 也接受同名操作。

活动顺序、首轮上限、分组方式及调整条件属于团队实施规则，不是官方阈值或已验证的教育学结论。

运行行为测试：`node --test modules/guidance/tests/*.test.ts`。设置 `STUDY_DATA_DIR` 指向本地私有 CSV 目录后，额外核对三名正式展示案例与实际题目引用；未设置时该项明确跳过。合成测试不含原始赛事记录。整体运行与验证入口由上层统一提供，进度统一记录在 [项目日志](../PROJECT_LOG.md)。
